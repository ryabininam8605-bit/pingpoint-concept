# Ping Point
Сайт комнаты настольного тенниса в Брянске. Рабочий вариант — `1-neon`; остальные варианты — архив. Python 3.11+, без внешних пакетов и сборки; Node нужен только для проверок. Подробности запуска — `README.md`; источник истины о поведении — код.

## Точки входа
- `server.py` — HTTP/API, cookie-сессии, CSRF и общая SQLite.
- `1-neon/index.html` — главная, цены, занятость и поиск партнёра.
- `1-neon/cabinet.html` — профиль, объявления, документы и свои брони.
- `1-neon/admin.html` — административные формы и серверный preview суммы.
- `1-neon/community.js` — локальные профили/объявления, согласия, UI, `PP.allowedPostStarts`.
- `1-neon/shared-booking.js` — серверный адаптер `BookingAPI`/`AdminAPI` и кеш занятости.
- `1-neon/booking.js` — создание, тестовая оплата и перенос брони.
- `tests/check.mjs` — единая проверка синтаксиса, Node- и Python-тестов.

## Команды
Из корня проекта, установка зависимостей не нужна:
- `python server.py --port 8767` — запуск из README; открыть `/1-neon/index.html` на `127.0.0.1`.
- `python server.py --port 8765 --demo-payments` — проверенный запуск текущего локального просмотра; имитация оплаты без денег и кода двери.
- `python server.py --port 18769 --database .acceptance-runtime.sqlite3` — проверенный изолированный запуск: HTTP 200, две cookie-сессии, бронь/занятость/409/отмена/освобождение.
- `node tests/check.mjs` — проверено: 8 проверок синтаксиса, 13 Node- и 13 Python-тестов.

## Что легко сломать
- Статический `http.server` не обслуживает бронирование. Сервер по умолчанию использует `.data/bookings.sqlite3`; для QA нужна временная база без реальных данных. Брони общие, профили и объявления остаются в браузере; старые локальные брони не импортируются и не занимают общую сетку.
- `.env.example` — только справочник: `PP_ADMIN_LOGIN` и `PP_ADMIN_PASSWORD` задаются в окружении процесса, файл автоматически не загружается. Без обеих переменных админский вход закрыт; localStorage не даёт серверных прав.
- Подключать `community.js` → `shared-booking.js` → `booking.js` (где он используется); обновлять версии изменённых скриптов на страницах. Сохранять публичные API и `pp:change`. Ждать `BookingAPI.ready` и `refreshAvailability`; `availabilitySync` содержит только загруженный серверный кеш, `[]` при loading/error не означает свободное время. Проверять `availabilityState`; локального fallback нет.
- Перенос сохраняет предоставленную скидку `promoTerms`; не проверять её как новую продажу. Ручную сумму админки предварительно считать через `quoteManualBooking`, передавать `expectedAmount`; сервер возвращает 409 `QUOTE_CHANGED` при расхождении. Закрытие окна загрузки отменяет продолжение.
- Не удалять данные пользователя и не принимать согласия за него. Для браузерной QA использовать `localhost`, если рабочий сайт открыт на `127.0.0.1`: порты не изолируют cookie, а hostname изолирует. HTTP-тестам нужны отдельные cookie jars и временная база.

## Как здесь работает Autopilot
