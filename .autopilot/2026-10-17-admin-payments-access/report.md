# Ping Point — результат сборки

Локальная программная часть принята из чистой копии.10 требований реализованы,3 ожидают сведения для настоящего подключения. Это не сдача работающей физической двери или боевого магазина.

## Готово

- Администратор видит серверных пользователей, даты регистраций и входов, включая зарегистрированных без броней. Контакты гостевых броней показаны отдельно.
- Сводка за выбранные даты показывает поступления, возвраты, разницу до комиссии, регистрации, брони и оплаты. Графики имеют подписи и точную таблицу. Тестовые деньги отделены от реальных; разница не названа прибылью.
- Игрок входит паролем и может добавить ключ устройства. Отпечаток, лицо или PIN выбирает устройство; сайт не получает биометрию. Аппаратный диалог ещё не проверен на устройстве клиента.
- После подтверждённой нетестовой оплаты владелец гостевой брони получает QR в этом браузере; после регистрации/входа он доступен в своих бронях на других устройствах. Одна регистрация, demo или test физического пропуска не дают.
- Сервер разрешает повторное предъявление QR только от начала включительно до конца исключительно. Отмена, возврат, перенос и неявка отзывают прежний пропуск. Неоплаченная бронь и посторонний пользователь доступа не получают.
- Пропуск целиком виден при первом открытии на375×812, белые полосы прокрутки админки убраны. Доставка кода по SMS не обещается.

Подтверждено независимым checker: запуск с нуля, регистрация/пароль/админка/пользователи/графики через браузер; собственный локальный HTTP mock сценарий оплаты, приватности, денег и граничных моментов доступа.10 проверок синтаксиса,36 Node и38 Python тестов без ошибок. Настоящий SVG QR независимо декодирован. Реальные списания, возвраты, SMS, публикация и открытие двери не выполнялись.

## Что нужно для подключения

Пользователь сообщил: «сайт есть. скажу позже» и по СКУД «уточню отвечу позже, как даст ответ клиент». Эти пункты сохранены ожидающими, не выданы за выполненные.

| Что ожидается | Настройки без значений |
|---|---|
| Вход администратора на рабочем сервере | PP_ADMIN_LOGIN, PP_ADMIN_PASSWORD |
| Домен HTTPS | PP_PUBLIC_ORIGIN |
| Магазин и режим ЮKassa | PP_YOOKASSA_SHOP_ID, PP_YOOKASSA_SECRET_KEY, PP_YOOKASSA_MODE |
| Подтверждённая схема чеков продавца | PP_RECEIPT_MODE и относящиеся к выбранной схеме параметры из .env.example; налоговые значения не угаданы |
| Модель, протокол контроллера и QR-считывателя | PP_SKUD_DEVICE_TOKEN, PP_SKUD_DOOR_ID после согласования; нужны адаптер конкретного оборудования и полевая проверка |

Значения задаются владельцем в окружении процесса сервера; образец — .env.example. Файл .env автоматически не читается. Generic online-коннектор подготовлен, его настройка сама по себе не доказывает совместимость считывателя. При отсутствии настройки интерфейс прямо сообщает, что интеграция не подключена.

## Что не вошло

Публичное размещение, SMS и массовый перенос прежних локальных профилей/объявлений. Продление/отзыв серверных согласий и удаление/восстановление серверного аккаунта пока не поддерживаются; UI сообщает об этом и сохраняет доступ к оплаченным броням и QR. Перенос оплаченной брони с изменением суммы требует отдельного расчёта. Физический подсчёт людей по общему QR не обещается.

## Что исправлено при проверках

Код-ревью выявило четыре коротких дефекта: устаревший профиль после смены пароля, обещание SMS, начальную прокрутку QR и светлые полосы админки. Все закрыты и повторно проверены. В чистом окружении дополнительно обнаружились неописанные dev-зависимости независимого decoder; теперь они закреплены отдельным списком и устанавливаются одной командой. Assertions не ослаблялись.

## Что осталось после ревью

- Для публичного размещения несколькими процессами нужен общий ограничитель попыток входа; текущий работает в одном процессе и сбрасывается после перезапуска.
- Перед публичным размещением нужно ограничить поток неавторизованных проверок QR и срок хранения сессий/журнала, чтобы не раздувать SQLite.

Других расхождений между итоговым манифестом и независимой приёмкой нет. Внешние подключения остаются частичными открыто, аппаратная биометрия и дверь не проверены.

## Открыть и запустить

Рабочий сайт: http://127.0.0.1:8765/1-neon/index.html . Для показа админки без изменения рабочей базы оставлен http://localhost:18770/1-neon/qa-admin.html — отдельная синтетическая база, деньги и дверь отключены, на экране предупреждение. Это временный локальный preview, не публичный административный адрес.

Из корня проекта: `python -m pip install -r requirements.txt`, затем `python server.py --port 8765`. Перед перезапуском остановить прежний процесс на этом порту. Полная проверка: `python -m pip install -r requirements-dev.txt`, затем `node tests/check.mjs`; выбранный Python должен быть первым в PATH. Сценарий чистого Windows venv дан в README.

Память проекта — AGENTS.md, состояние незавершённых работ — .autopilot/PROGRESS.md. Границы модулей описаны в docs/architecture.md, четыре принятых решения — docs/adr/, словарь — CONTEXT.md. Подробности независимой проверки — acceptance-result.md, визуальной — visual-qa.md в этой папке.
