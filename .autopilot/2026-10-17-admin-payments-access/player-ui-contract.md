- Порядок scripts: `community.js` → `shared-booking.js` → `shared-account.js` → inline страницы / `booking.js`. Все изменённые page assets имеют версию `20261017a`; admin.html принадлежит04.
- `AccountAPI.ready`, `documents()`, `register(options)`, `login({phone,password})`, `logout()`, `me()`, `updateProfile(patch)`, `changePassword(currentPassword,newPassword)`, `supported()`, `listPasskeys()`, `deletePasskey(id)`, `addPasskey()`, `loginPasskey(phone)`, `authForm(container,options)`, `mountSecurity(container)`.
- `CommunityAPI` auth/profile методы перенаправлены на сервер. `_setServerUser`/`_serverMe` — узкий внутренний мост к сохранённой localcommunity базе по точному серверному ID; старые профили/объявления/ключ локальной сессии не удаляются и не дают входа. Пароли не сохраняются. Повторное получение неизменного profile не эмитит `pp:change` (иначе bindCabButton создавал цикл запросов).
- Регистрация отображает canonical документы и передаёт явно отмеченные `{accepted:true,version,hash}`. DOCS_CHANGED обновляет список с пустыми checkbox. Вход паролем остаётся доступен при отсутствии/отмене WebAuthn; браузер получает options и отдаёт base64url credential JSON. На security-панели подключение/удаление ключа и смена пароля.
- `BookingAPI.session()` — текущий cloned session; `request(path,body?)` — same-origin JSON с текущим CSRF; `refreshSession()`; событие `pp:session` с session snapshot. Любой response.csrf обновляет токен до следующего POST, включая account auth/password/logout. Admin04 использует этот контракт.
- `BookingAPI.refreshPayment(id)` → `/api/payments/{id}/refresh`; `checkoutUrl(payment)` отклоняет не-HTTPS, credentials, относительный и невалидный URL. Redirect не подтверждает оплату. Только demo использует confirm; live/test не собирают номер карты/CVC и не используют декоративный QR.
- `BookingAPI.getAccess(id)`, `accessHTML(access)`, `mountAccess(container,id)` → функция cleanup. Один server-issued SVG показывается как image data URI; payload не генерируется и не используется fallback. Неоплачено/test/expired/revoked скрывают изображение. Ошибка чтения тоже скрывает QR и даёт повтор; polling прекращается на detached container. Рядом явное предупреждение unconfigured СКУД и правила [начало,конец), Москва, повторный вход.
- Гостевой cabinet показывает cookie-owned брони без регистрации. Перед redirect sessionStorage хранит только booking ID `pp_checkout_booking`, при возврате открывается #bookings; ID не даёт доступа без cookie. Действия оплаты/возврата сверяются вручную с сервером.
- Server delete/restore/revoke PD/renew registration consents не поддержаны backend: UI сообщает об этом и не создаёт фиктивного успеха. Consent_public/ads остаются явно локальными. Export честно помечен частичным, добавляет серверный профиль/брони и локальные записи.
