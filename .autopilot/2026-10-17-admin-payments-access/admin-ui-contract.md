# UI администратора — 04

- `admin.html` загружает `community.js → shared-booking.js → admin-insights.js`, версия `20261017a`. Игровая авторизация не используется для прав администратора. Существующая серверная admin login/logout и операционные настройки/промо/manual quote сохранены.
- `window.AdminInsights`: `request(path,query)`, `mountAnalytics(root,alive,{onError,openBooking})`, `mountUsers(...)`, `mountPayments(...)`, `mountIntegrations(...)`; mount возвращает refresh. Публичные чистые renderer-функции `analyticsHTML`, `usersHTML`, `paymentsHTML`, `integrationsHTML`, `errorHTML` используются и UI, и тестами. Все данные выводятся с HTML escaping; GET credentials same-origin/no-store, timeout12с, error/retry. Единственная новая mutation в карточке — сверка провайдера через `BookingAPI.request('/api/payments/{id}/refresh',{})`, с текущим серверным CSRF.
- Сводка использует только `/api/admin/analytics` для денежных карточек и графиков. 7/30/90/custom, Москва, не более366 дней, live/test. Копейки видны точно, net обозначен как разница поступлений и возвратов до комиссии. SVG имеет уникальные целые ticks для счётчиков и крайние даты с безопасными anchors. Раскрываемая таблица содержит все нулевые дни и точные суммы. Старая загрузка и сегодняшние брони сохранены в операционном раскрытии с отдельным пояснением о тестовых бронях, прежние money-by-game-date KPI убраны.
- Пользователи — `/admin/users` с q/page/pageSize30, включая без броней. Карточка `/admin/users/{id}` показывает даты, неподтверждённый телефон, регистрационные согласия `docVersion`, брони и `booking.payment`. Контакты гостевых броней остаются отдельны; отметка локального профиля не называется серверным кабинетом.
- Реестр платежей использует `/admin/payments?mode=live|test&from&to&status`. Период явно по createdAt попытки, не по денежному событию. Накопленные возвраты по платежу не выдаются за возвраты в периоде. Вывод по30 строк с расширением, CSV сохраняется и защищает формулы. Неизвестный test трактуется тестовым.
- Интеграции — `/admin/integrations`, журнал — `/admin/access-events?limit=100`; DTO allowlist без QR. Generic коннектор не обещает совместимость с неизвестной моделью и полевой проход. Кнопки открытия двери отсутствуют. Симуляция маркируется отдельно.
- `payment_review`, `refund_pending`, `requires_review` видимы; действия возврата и сверки остаются серверными. Pending возврат явно ещё не возвращённые деньги, доступ закрыт. При переносе пояснено, что старый QR отзывается. Прежний код не выводится в admin списке/карточке. Manual payment доступен только при явном demoPayments и подписан тестовым.
- Локальные community/legacy consent панели и sidebar подписаны. Новые регистрационные согласия находятся в серверной карточке пользователя. Администратор не редактирует и не удаляет аккаунты: эта операция не входила в задачу.

RED: до UI навигация не содержала отдельного users route; renderer/request seams отсутствовали. Пять тестов упали именно на отсутствии этих возможностей. Затем тест пустого series выявил ошибку date[-1], исправлена. Существующие login/manual-preview тесты сохранены зелёными.

Визуальный QA выполняет root на отдельной синтетической базе; executor браузером не управлял.
