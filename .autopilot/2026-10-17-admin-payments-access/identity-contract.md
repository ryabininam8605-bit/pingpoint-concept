# Фактический контракт 01

## Identity и UI 03
- `GET /api/account/documents -> {list:[{id,version,hash,url}]}`: только три обязательных документа регистрации `consent_pd`, `community_rules`, `policy`; hash вычисляет сервер из канонического HTML. Клиент отображает ссылки, получает явные checkbox и отправляет `consents:{[id]:{accepted:true,version,hash}}`. Boolean true без версии/hash не принимается. Изменившаяся ревизия —409 DOCS_CHANGED, повторно показать документы. Никаких автоматических согласий.
- `/register`: `{phone,password,name,ageGroup:'adult'|'minor',guardian?:{fio,phone},consents}`. Пароль10–128 символов; minor должен указать другое лицо/телефон. Ответ `{user,csrf}`. Телефон служит логином; `phoneVerified:false` всегда. Local1234 не даёт серверного доступа.
- `/login`: `{phone,password}`; `/logout` `{}`; ответ `{user,csrf}`. `/account/me -> {user:null|profile}`. На login/register/logout/password и passkey-login cookie и CSRF меняются; адаптер обязан обновить CSRF или заново GET `/api/session`. Старые bearer-like cookies уже не действуют.
- Profile совместим с CommunityAPI.meSync: id,name,phone `+7…`, phoneRaw `7…`,createdAt,lastLoginAt,phoneVerified,ageGroup,guardian,age,level,hand,style,about,tg,showPhone,photo,deletion,consents,hasPhoto,demo:false,docsOk,publicOk:false,publicCond:null,outdated,completeness:{pct,missing}. Фото может бытьnull; существующий avatar helper строит avatar. `consents:{id:{version,hash,active,acceptedAt}}`. Публичное согласие на объявления пока локальный community слой: server publicOk не имитирует такое согласие.
- `/account/profile` POST принимает только name,age,level(`novice|amateur|confident|pro`),hand(`right|left`),style(`attack|defense|universal`),about<=600,tg<=64,showPhone bool,photo nullable PNG/JPEG/WebP dataURL<=45000. id/phone/roles/consents из произвольного profile body не изменяются. Ответ `{user}`. `/account/password` `{currentPassword,newPassword}` отзывает остальные сессии и возвращает `{ok:true,csrf}`.
- WebAuthn options возвращаются напрямую WebAuthn JSON (не `{options}`). Credential JSON body `{credential}` с base64url полями. Login options требуетphone; register options требует вошедшую сессию. Перевод ArrayBuffer↔base64url —UI. `/passkeys`GET `{list:[{id,name,createdAt}]}`, `/passkeys/delete`POST `{id}`. Отмена browser dialog не вызывает verify и не мешает парольному входу. UP+UV обязательны. Origin фиксирован PP_PUBLIC_ORIGIN либо `http://127.0.0.1:<port>` при loopback bind; aliaslocalhost не тот же origin.

## Схема сервера и точки интеграции 02
- Существующий factory `create_server(host,port,db_path,demo_payments,admin_login,admin_password)` сохранён. PP_PUBLIC_ORIGIN читает env; only canonical HTTPS origin, добавляет public host allowlist и Secure cookie. Непроверенные Forwarded/X-Forwarded-* не используются. Зависимости см.requirements.txt, установить `python -m pip install -r requirements.txt`.
- Store.transaction перед action добавляет пустые коллекции `users`, `authChallenges`, `credentials`, `paymentOperations`, `accessGrants`, `accessEvents`, `refundOperations`. Исходные поля/данные не стираются. SQLite sessions мигрируется добавлением `user_id`TEXT. `session` dict `{id,csrf,admin,userId}`. `self.server.accounts` — identity.Accounts.
- `owns_booking(booking,session)`: при booking.userId разрешает только совпадающий session.userId; иначе guest cookie owner. `private_booking(db,id,session)` также разрешаетadmin. Регистрация/login/passkey-login присваивает только guest-записи текущей cookie; никакого поиска/claim по телефону. Новая бронь при account session сохраняетuserId; manual admin бронь не приписывается самомуadmin.
- `Handler.dispatch` выполняетGET session, account_routes и admin-login/logout, проверяетadmin authority, затем existing `store.transaction(operation)`. Внешний IO платежей/reader должен идти в dispatch до последней transaction, а изменения —другими короткими store.transaction. Webhook/reader исключенияCSRF добавляет02 с собственными защитами в Handler.api. `APIError` и `identity.IdentityError` маппятся в единыйerrorJSON.
- GETsession сейчас добавляетuser/capabilities accounts/passkeys и честные временные payments demo|disabled/access unconfigured;02 заменяет capabilities и `/admin/integrations` данными своего настоящего config service. Отсутствующие ключи не должны объявлятьсяconfigured.
- `/admin/access-events` берёт db.accessEvents `{at,bookingId?,doorId,result,reason}`, сортируетdesc, отдаёт толькоallowlist, `?limit=1..200`, безpayload.
