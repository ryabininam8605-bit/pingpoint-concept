# Кабинет администратора, оплата и доступ

## Задача
Владелец видит всех зарегистрированных игроков и реальные деньги; оплативший посетитель получает пропуск на время игры. Пользователь сообщит оборудование СКУД и данные магазина/домена позже. Эти интеграции готовятся и проверяются локально, но не объявляются подключёнными к реальной двери или магазину.

## Решение
Расширяется выбранный 1-neon: защищённая админка с пользователями, датами регистрации, платежами и понятными графиками. Серверные аккаунты входят по телефону как логину и паролю; телефон при этом не считается подтверждённым. Дополнительный вход ключом доступа устройства (WebAuthn: отпечаток/лицо/PIN выбирает устройство), биометрия не поступает на сайт. Гость получает QR в своей брони, вошедший игрок также видит его в кабинете. Проход многократный только на интервале [начало, конец) по Москве.

## Истории и приёмка
| Метка | История | Приёмка |
|---|---|---|
| R01 | Администратор входит в свой кабинет | Серверные права обязательны для каждой операции, настройки и старые брони сохраняются |
| R02, R03 | Видит зарегистрированных, даже без броней | Серверный реестр с ID, именем, логином, датой регистрации, последним входом, количеством броней; поиск/пагинация, отдельная отметка неподтверждённого телефона; нет seeded/local demo пользователей |
| G01 | Игрок регистрируется и входит паролем | Пароль хешируется scrypt с солью; разумные длины, ограничения попыток, общие ошибки входа, сессия ротируется, logout закрывает права; одинаковый телефон в локальном профиле не даёт серверных прав |
| G01.1 | Включает ключ доступа и входит им | WebAuthn через зрелую библиотеку, проверка challenge/TTL/одноразовости/origin/RPID/UP/UV/подписи; настройка после входа паролем; удаление своего ключа; отмена диалога сохраняет парольный вход; при отсутствии поддержки понятное сообщение |
| R02.1 | Сохранность и связь брони | Аддитивная миграция SQLite, регистрация не переписывает старые локальные профили; только текущие гостевые брони cookie привязываются к вошедшему аккаунту, чужие по телефону не присваиваются; свои брони доступны со второго устройства после входа |
| R03.1 | Подтверждает документы сам | Существующие требования согласий/возраста сохраняются, регистрационные согласия и revisions проверяются и записываются на сервере; никакого автоматического принятия, прав администратора или контакта третьим лицам |
| R04 | Видит понятные графики за период | Выбор 7/30/90 дней и дат; тренды регистраций, оплат/возвратов и броней; подписи осей/единиц/дат, точные значения и доступная таблица; нули и ошибки видимы, мобильный экран не распирается |
| R05 | Оплачивает через ЮKassa | Сервер создаёт redirect payment по серверной сумме в RUB, сохраняет idempotency key до запроса, возвращает confirmation_url; карточные реквизиты сайт не собирает; нет ключей в браузере |
| R05.1 | Повторяет после обрыва | Одна активная попытка оплаты, устойчивые keys/параметры, HTTP вне SQLite write-lock, таймаут не создаёт новую транзакцию; уведомления повторяемы, статус запрашивается через аутентифицированный API провайдера |
| R05.2 | Возвращается после оплаты | Redirect и webhook body не доказательство; проверяются provider ID, metadata/связь, сумма, валюта, paid, test; можно повторить сверку в кабинете; late success не пересекается с новой бронью: явный conflict/requires_review без пропуска, видимый администратору |
| R05.3 | Отменяет/переносит | Не изображать возврат денег локальной записью. Реальные возвраты имеют отдельные persisted операции, сверяются с провайдером; неизвестный исход виден pending/review. Существующая политика отмен сохраняется. Перенос без изменения цены сохраняется и отзывает старый пропуск; изменение суммы реальной оплаченной брони явно отклоняется до отдельного расчёта, без имитации списаний/возврата |
| R06, R07 | Видит полученные и возвращённые деньги | Расчёт по paidAt/событиям подтверждённого возврата (не дате игры и не дате создания попытки), Москва; gross, refunds, net=gross-refunds, количество, способ, статус, ID брони; рубли с копейками. Это поступления до комиссии, не прибыль. Тестовые платежи отдельно и по умолчанию не в реальной выручке |
| R08 | Подключает устройство СКУД | Пока модель неизвестна: честная панель «СКУД не подключена», документированный аутентифицированный online-connector и симулятор, без команд реальной двери. Вендорный адаптер/полевое испытание ожидают модель клиента |
| R09, R10 | Получает настоящий читаемый QR после оплаты | Единый серверный непрозрачный payload без PII, стандартизованный QR с quiet zone, одинаковый в завершении и кабинете. Выдача только владельцу; административные списки/логи токенов не содержат. Регистрация без оплаты не даёт QR |
| R11, G02 | Проходит повторно весь сеанс | Аутентифицированный reader запрос проверяет токен и текущее состояние, start<=serverNow<end, оплачено, не тест, не отменено/возвращено/перенесено. Два сканирования в сеансе разрешены; ровно конец запрещён; раньше начала запрещено |
| R11.1 | Код отзывается при изменении брони | Отмена, полный/частичный возврат с закрытием брони, перенос, неявка блокируют доступ; новый код при переносе, старый не оживает. При ошибке/недоступности сети online-check запрещает, а UI не обещает проход |
| R08.1 | Администратор диагностирует доступ | Статусы интеграций без секретов, события разрешён/отказ с причиной и временем, без payload; тестовые операции явно маркируются и никогда не допускаются реальным reader endpoint |

## Решения по реализации
- T2, четыре плотных таска: фундамент аккаунтов/данных/аналитики; платежи+доступ; UI игрока; UI администратора. Первые два последовательно владеют сервером, затем два UI работают по разным файлам.
- Сохраняются Python 3.11+ HTTP + SQLite и существующие JS/HTML. Новые модули identity, analytics, payments, access уменьшают смешивание полномочий. Схема расширяется аддитивно с defaults; исходные записи/документы не стираются.
- Зависимости: webauthn==3.0.1 (проверка WebAuthn), qrcode==8.2 (настоящий QR SVG без Pillow), их зависимости фиксируются в requirements.txt; остальные операции stdlib. Тестовый decode QR допускает отдельный dev decoder, не runtime зависимость. Никакой самодельной криптографии WebAuthn и декоративной QR матрицы.
- Пароль 10–128 символов, scrypt, постоянное время сравнения; ограничение попыток/IP и логин, не доверять forwarded headers. Восстановление по неподтверждённому телефону не делается. Изменение пароля требует текущего пароля. Нельзя выдавать права по localStorage.
- Конфигурация окружения, без автозагрузки .env: PP_PUBLIC_ORIGIN (HTTPS для реальной оплаты), PP_ADMIN_LOGIN/PASSWORD, PP_YOOKASSA_SHOP_ID/SECRET_KEY, PP_YOOKASSA_MODE=test|live, PP_RECEIPT_MODE и явные налоговые параметры при отправке чеков; PP_SKUD_DEVICE_TOKEN/DOOR_ID. Без фактов/ключей интеграция disabled. Не выдумывать НДС, фискализацию, адрес устройства или магазин. Настройка passkey от явного origin/RPID либо безопасного loopback origin.
- Существующий demo mode остаётся только явным локальным флагом, не может выдавать реальный доступ. Provider test=true изолирован. Local mock provider/reader тестирует контракт без сетевых обращений к реальным системам.
- Брони/платежи/доступ используют серверные суммы и время, целые копейки на денежных границах. Возвраты/идемпотентность/истечение учитываются транзакционно. Внешний HTTP выполняется между подготовкой durable operation и атомарным применением результата.
- Webhook не требует браузерного CSRF, но перед применением читает объект у провайдера; остальные POST с CSRF, reader только отдельный bearer credential и bounded payload; секреты/QR не в URL и логах. Cookies Secure для configured HTTPS, origin/host allowlist не из непроверенного proxy header.
- Админские старые локальные community/consent данные явно подписаны локальными, не выдаются за общий реестр. Серверный профиль синхронизируется в локальный community слой только как UI compatibility и не даёт прав серверу.

## Границы и швы
См. interfaces.md. Check: node tests/check.mjs. Приёмка проверяет реальные HTTP сессии, mock API провайдера, фальшивые и повторные webhook, парольный вход, WebAuthn подписанные assertions, QR независимым decoder и граничные моменты доступа.

## Вне рамок
Публикация и настоящие финансовые операции в этой локальной сборке не выполняются. Команды открытия двери не отправляются. Массовый перенос старых локальных профилей/объявлений и подтверждение телефона по SMS не заявлены: телефон служит логином, а не доказательством владения контактами.

## Открытые места
R05: магазин ЮKassa, домен/HTTPS и параметры фискализации пользователь сообщит позже. Код интеграции, конфигурация и mock-проверки входят; боевое подключение остаётся явно неактивным.
R08/R11: модель/протокол СКУД, считыватель и полевая проверка неизвестны. Online-authorization и QR проверяются локально; вендорная интеграция ожидает сведения, не заменяется притворным открытием.
Количество физически проходящих по групповому QR не подтверждено: приложение разрешает повторные проверки на бронь в указанный интервал; физический счёт людей не обещается. Число игроков ограничивается существующей бронью (до четырёх).
G01: сайт не выбирает за устройство отпечаток вместо PIN/лица. Аппаратное подтверждение WebAuthn проверяется при доступном устройстве; программный подписанный тест обязателен.
