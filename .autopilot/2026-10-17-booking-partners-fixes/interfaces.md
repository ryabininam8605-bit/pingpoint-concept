# Границы, решённые в спецификации
- Стек: самодостаточные HTML со встроенным JS, общие community.js и booking.js, без framework и сборщика.
- CommunityAPI хранит профили, согласия, объявления; PP утилиты. BookingAPI отвечает за занятость и брони. Сохранять публичные вызовы и события pp:change.
- Время в минутах от полуночи, шаг 30; days 0–6 соответствуют существующим DAY_SHORT; timeFrom nullable. Общий helper PP.allowedPostStarts(times, settings?) используется формой, validatePost и nextSlots. Данные поста не переименовывать.
- Форму объявления и продолжение документов исправлять в cabinet.html. Общий sheet и стили прокрутки — community.js. Калькулятор/цены/сетка — index.html. Обновить версии скриптов на главной, кабинете, админке.
- Старые записи пользователя сохранять; генератор демонстрационных броней отключить, из занятости исключать только явные demo записи. Не удалять реальные брони, профиль, согласия или объявления.
- Не обходить согласия/авторизацию. Не принимать согласия за пользователя в реальном браузере; регрессионные тесты используют изолированные фикстуры.
- Изменяем только pingpoint-concept. Папка варианты — архив и не обслуживает запущенный адрес.
- Общий сервер и его контракт ожидают ответа пользователя; зависимые изменения не начинать до ответа.
- Команда проверки создаётся первым исполнителем: node tests/check.mjs; один набор: node --test tests/*.test.mjs. Без сторонних зависимостей.
- Исполнители не коммитят, не правят .autopilot и память; родитель ведёт журнал и коммиты.

## Подтверждённый сервер
Предыдущая запись об ожидании источника заменена ответом «На сервере этого сайта».
- Сервер: Python 3.11 stdlib ThreadingHTTPServer + SQLite, атомарные транзакции. Запуск: python server.py --port 8767 --demo-payments. База в .data/ (gitignored). Проверка: python -m unittest discover -s tests -p "test_*.py", затем node tests/check.mjs (создать во втором таске).
- Таск 01 владеет server.py, 1-neon/shared-booking.js, tests/test_*.py, tests/shared-booking*.mjs, README.md. Существующий community.js не меняет; адаптер заменяет методы экспортированных BookingAPI/AdminAPI, и публикует BookingAPI.refreshAvailability(date), BookingAPI.availabilityState(date) -> {status:'loading'|'ready'|'error',error?}, BookingAPI.ready -> Promise. availabilitySync возвращает только кеш сервера, без локального fallback. Разрешено дополнить этот контракт сообщением оркестратору.
- Таск 02 подключает shared-booking.js ПОСЛЕ community.js и ДО booking.js на главной, кабинете, админке; добавляет await refreshAvailability в UI, guards loading/error. В адаптере нет DOM верстки; асинхронный bootstrap готов до создания брони, вызов Booking.open ждёт readiness и refresh.
- Таск 02 владеет всеми существующими 1-neon/*.html, community.js и booking.js, tests/check.mjs, tests/community*.mjs; ему принадлежит PP.allowedPostStarts helper и исправление demo seed. Не меняет сервер или shared-booking.js.
- Общие владельцы брони — серверные непредсказуемые сессии. Не принимать за аутентификацию произвольный телефон, userId или localStorage admin. Административные booking операции защищены серверной сессией.
- Источник публичной занятости содержит только время/статус/тариф. Локальный login профиля не даёт доступ к чужим серверным броням. Гостевые брони своего браузера доступны в кабинете после входа. Межбраузерный вход в профиль не переносить в этой задаче.

## Реализованный контракт таска 01
BookingAPI.ready: Promise; refreshAvailability(date,excludeId?) и refreshAllAvailability(dates,excludeId?); availabilityState(date,excludeId?) возвращает {status,error?}; availabilitySync — только серверный кеш или []. BookingAPI.demoPayments — boolean. Без изменения ответа повторное обновление не эмитит pp:change.
Запуск: python server.py --port 8767 --demo-payments [--database PATH] [--bind 127.0.0.1]. Настройки админа: PP_ADMIN_LOGIN и PP_ADMIN_PASSWORD (значения не хранить в repo). Серверная cookie-сессия + CSRF, общая SQLite.
Тестовая оплаченная бронь code:null/test:true. UI не должен рисовать реальный код входа или обещать его отправку; показать, что это тестовая бронь и код доступа не выдаётся. Реальная оплата и контроллер замка не подключены.
Для CUA-проверки формы: .autopilot/<dir>/qa-bootstrap.html копируется под 1-neon/qa-bootstrap.html в отдельную временную QA-копию, запускаем server.py на8768 с отдельной базой. Клонирует только существующего seed-пользователя и его принятые тестовые документы. Реальные согласия в пользовательском браузере не нажимать.

## Исключение порядка запуска
Для сокращения ожидания таск 02 начинает разработку на уже проверенном и staged контракте таска 01 параллельно только его узкой правке промокодов. Зоны не пересекаются; сервер и адаптер не меняют публичный контракт. Коммит 02 разрешён только после принятого и закоммиченного 01. Пользователю объявлено явно. Требования и критерии не меняются.

## Уточнение переноса из проверки таска 01
Сервер сохраняет promoTerms в брони как уже предоставленные условия скидки. Для переноса нельзя повторно проверять доступность промокода для новой продажи. Адаптер quote({start,dur,rackets,promoTerms}, promoCode) использует snapshot при его наличии. UI переноса передаёт b.promoTerms или получает authoritative quoteReschedule. Лимит промокода потребляется атомарно при каждом переходе в paid, включая административные действия.

## Финальная доводка F1
Область F1 объединяет server.py, shared-booking.js, admin.html, booking.js и перечисленные тесты; прочих активных исполнителей нет. Прежние административные amount и note сохраняют семантику: изучить исходный AdminAPI.createBooking в cfa62e6, серверно валидировать, не доверять обычному клиенту. Новых цен и ролей не вводить. Подтверждённый промокод preview не должен зависеть от случайно прогретого клиентского кеша. Закрытие loading-sheet — отмена продолжения.

## Контракт F1 (в реализации)
POST /api/admin/bookings/quote — авторизованный серверный preview тарифа или ручной суммы; обычному клиенту не доступен. createBooking администратора может получать expectedAmount, при расхождении сервер отклоняет запись вместо молчаливой смены цены. Ручная сумма — неотрицательное safe integer, note максимум200 символов. Клиентская бронь не задаёт amount/note. Конкретный контракт ответа зафиксирован в исходниках и финальном блоке исполнителя.

## Реализованный контракт F1
AdminAPI.quoteManualBooking(options) -> Promise<quote>; POST /api/admin/bookings/quote возвращает quote с tariffTotal. createManualBooking принимает optional expectedAmount и возвращает409 QUOTE_CHANGED при расхождении. Ручная сумма и note доступны только серверной сессии администратора; клиентская сумма не доверенная. Заметка сохраняется, loading-dismissal отменяет продолжение в обеих формах. Полный check:8syntax,13Node,13Python.

## Локальный просмотр и изоляция QA
Готовая версия запущена на прежнем адресе 127.0.0.1:8765 (python server.py --port 8765 --demo-payments). Это тот же сервер и .data/bookings.sqlite3, что в примере README с 8767. Для будущих браузерных QA-копий использовать hostname localhost при рабочем 127.0.0.1: cookie не разделяются портами; localStorage разделяется. Обычные HTTP-тесты используют отдельные cookie jars и временные базы.
